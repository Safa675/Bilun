# Wave A focused-detector implementation map — 2026-09-27

This is the dependency map for the 18 focused detector groups deferred by `reports/rule-engine-surfacing/2026-09-19-migration-scope.md:186-190`. It is planning evidence, not an activation or a change to billing behavior. The inspected baseline is `bbf9acaf` (PR #96). The companion seven broad-engine groups are outside this map. The accepted rollout is staged checkpoints with one final activation: all 25 groups must be represented, Compliance must remain strictly unpriced, sourced financial findings must live separately, statuses and identities must be honest, and existing totals must not change.

## Current product boundary

All 18 focused detectors already execute in the legacy `analyze_claim` path (`src/bilun/domain/billing/engine.py:235-395`). The canonical evaluator currently recognizes only five original rules (`src/bilun/domain/billing/rule_findings.py:23-65`) and independently invokes those five (`:304-325`); its result is projected into the patient report (`src/bilun/domain/billing/patient_report.py:82-84`). Adding the deferred groups by calling each detector again in that evaluator would duplicate work and risk divergent legacy/product output. The implementation must reuse one runtime result or move invocation to one canonical producer while preserving the legacy flat result. This follows `plans/billing/2026-09-18-rule-engine-surfacing-audit-plan.md:337-343`.

There are **18 groups and 30 possible emitted rule IDs**: 15 single-ID groups, two IDs each for conditional EK-2D and dental GA, and 11 radiation-family IDs. The inventory's `kind:radiation_oncology` is a synthetic grouping label, not a runtime `rule_id`; the runtime forms `radiation_oncology.<rule_kind>.<family_key>` (`src/bilun/domain/prose_rules/radiation_oncology.py:73-113,267-285`). Do not key the canonical registry only by the inventory grouping.

The canonical finding ID is built from `(rule_id, patient_id, claim_id, line_kind, line_id)` (`src/bilun/domain/billing/rule_findings.py:68-79`), and findings are deduplicated by that ID (`:328-345`). The cohort projector rejects a claimed line finding when its canonical `line_id` and source line ID disagree or are absent (`src/bilun/domain/billing/cohort_compliance.py:133-188`). Therefore a procedure code, date, or claim ID cannot substitute for a real offending line ID.
