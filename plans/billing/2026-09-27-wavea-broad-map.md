## Minimal shared contract

1. Introduce a seven-entry **family adapter registry**, not a 496-ID dispatch allowlist. For each active JSON row, derive and validate `(family, rule_id, action.billable, condition, source locator, source corpus)` from the loaded corpus. Fail the inventory gate for duplicate/missing IDs, malformed actions, unknown source family, or a changed 496-ID baseline until reviewed. Preserve the raw `billable` value and full authored action in evidence. Map matched `false` to a rule-specific adverse candidate, matched `true` to a nonviolation positive/permission candidate, and matched `null` to `review_required`; payment traceability maps to `traceability_info` irrespective of `billable`. `billable=true` does not universally mean “must bill”: `1.8.2.(3).ek4d_exempt_no_copay` permits billing while forbidding copay, and `KALP_VE_DAMAR_CERRAHİSİ-2.anjiyo_kdc_kardiyolog_kesinti_degil` says a deduction is unwarranted. `billable=false` does not universally mean nonpayment: `1.5.2.(3).contracted_provider_must_accept` describes a service-access duty, and electronic report-format rules describe workflow duties. Classify each adverse row by its actual authored obligation; require applicable/billed context for a payment-denial claim, and verified violation facts for any unpriced regulatory finding. Otherwise present review/unavailable, preserving exact authored meaning. Missing provenance is `unavailable`, not a confirmed violation. Keep all 496 per-rule classifications in the inventory and transient evaluator; serialize actual matched rows plus compact status summaries and bounded details, never a visible static catalog of 496 rows per claim.
2. Keep the existing detector predicate as the decision authority. Add a per-rule evaluation adapter returning `matched`, `not_matched`, `missing_inputs`, `unsupported_predicate`, or `suppressed_by_prior_match`, together with exact missing/source keys and the original legacy row when matched. The adapter must call or instrument each family's existing predicate so its matched set and legacy rule/message/outcome/money values remain equivalent; additive source-identity metadata is allowed. Never maintain a second approximation of clinical logic. `RuleEvaluation.evaluation_status` stays `evaluated | missing_inputs | unavailable` (`rule_findings.py:20-21,116-124`); add an orthogonal `decision`/`reason` and optional source identity. `evaluated + not_matched` is a clean negative; a rule blocked by unavailable clinical facts is **not**. The condition-key requirement mapping must respect `_any` scalar fallback, annex lookup, optional dental false defaults, and branch gates (`gap_closing.py:95-180`; `dental_2_4_1.py:106-147`; `fatura_inceleme.py:74-88`). A known false predicate may produce `not_matched` while a separate unavailable predicate is recorded, but no rule may become `matched` on partial evidence. Unknown predicate shape, absent corpus, or missing source stays unavailable.
3. Evaluate once per `(patient_id, claim_id, rule_id, line_kind, line_id)` candidate. Use `PatientClaimContext.slice_for_claim` (`claims/patient_context.py:35-62`) before the six first-claim bridges; they currently select `ctx.claims[0]` or inherit its flat context. Drug combination already groups by drug-line `claim_id` (`drug_combination.py:395-439`); keep combinations claim-scoped, not arbitrarily attached to one drug. Dental alone is material-scoped: carry `material_line_id` and `claim_id` through its bridge instead of recovering identity from repeated material names (`dental_2_4_1.py:252-284`). Preserve the rule-order `break` after its first match per material (`:180-193`); later rules for that line are `suppressed_by_prior_match`, not clean negatives. When no authoritative line/header is available, emit an honest claim/group unavailable evaluation rather than fabricated line IDs.
4. Put only eligible adverse, unpriced matches into the existing `RuleFinding`/`claim_compliance.findings` contract. Its ID is already based on `(rule_id, patient_id, claim_id, line_kind, line_id)` and all money fields are null (`rule_findings.py:68-113`); claim-level broad findings use `line_kind="claim", line_id=None`, dental uses `"material"` and its real `material_line_id`. Positive billing instructions, review-required outcomes, and traceability information need a separate typed action/advisory stream with the same stable source identity and source label, outside compliance violation counts. The existing `RuleFinding` literals allow only compliance (`rule_findings.py:99-101`), so do not force those outcomes through it. Add optional `line_kind`/`line_id`, deterministic `evaluation_id` (a separate `claim_evaluation:` prefix over the complete five-part identity), and decision/reason fields to `RuleEvaluation`; serialize carried evaluations in `claim_compliance.py:68-77` and include identity in cohort dedup/validation. The current `(rule_id, claim_id)` key would erase multiple dental material evaluations (`cohort_compliance.py:65-130,191-209`). The finding serializer also copies `material_line_id` from the matching legacy row (`claim_compliance.py:22-29,33-65`), so the adapter must supply it for cohort validation. Maintain old-row fallback for cached evaluations without line identity, but do not merge a new line-level row into it. The cohort index currently counts every projected compliance finding (`cohort_compliance.py:373-407`), so advisory rows must not enter that collection.
5. Preserve financial semantics through the existing legacy projection. `analyze_claim` currently calls all seven motors directly (`billing/engine.py:186-226`) and exposes a flat list. Move those calls behind the canonical broad evaluator once; expose the same legacy list for existing internal callers and a typed batch for patient/public projections. `compute_patient_billing_report` already takes a canonical batch then projects it (`billing/patient_report.py:60-84`); integrate the broad batch there without a second detector pass. Do not add money to `RuleFinding` or infer zero from unknown amount. Compare `total_savings_try`, `total_risk_try`, recovery totals, and financial action identities before/after on identical fixtures and staged cache. Dental's legacy billed-risk computation stays on the legacy path (`dental_2_4_1.py:150-177`); new compliance findings remain unpriced.

## Data availability and source decisions by family

- **Dental:** The bridge derives procedure category and facility type but does not carry stable line IDs into its flat rows; age, board origin/inclusions, and some rule-specific clinical booleans are absent from the claim model (`dental_2_4_1.py:196-219,221-284`). Keep the evaluator's optional board/signatory false defaults exactly as implemented (`:62-67,129-146`). Test two identically named materials with different IDs and different conditions, plus an earlier winning rule suppressing a later one.
- **Drug combination:** Only six of 53 authored conditions are presently fully wireable; the corpus test derives this from `_WIREABLE_KEYS` and blocked/no-source sets (`tests/unit/domain/prose_rules/test_drug_combination_for_context.py:130-154`). `_check_combo_condition` already returns skip reasons, but the wrapper discards them (`drug_combination.py:225-251,263-321,432-439`). Preserve the matched set; preflight blocked/unknown keys for status so a prior ordinary nonmatch does not hide a schema blocker. Missing drug-class, PD-L1/ECOG/EMR history, treatment phase, or indication data stays unavailable. The existing weaker two-distinct-drug necessary condition is not upgraded to same-class proof (`:253-261`).
- **Fatura İnceleme:** Branch-null ORTAK rules apply to all claims; unknown branch or absent specialty/department must be explicitly skipped (`fatura_inceleme.py:74-88,128-139`). A first procedure's specialty is an imperfect proxy (`:142-160`); preserve its present match decisions until separately corrected. Preserve the guideline's own source locator and precedence label (`:1-19,91-118`). If a matched guideline instruction conflicts with a verified SUT instruction, keep the legacy detector row for decision parity but hold the new confirmed-compliance projection for source review; do not silently give the lower-priority guideline SUT authority.
- **Gap misc and treatment:** Their shared predicate returns only a boolean, so `False` currently conflates a real nonmatch, absent data, and unknown predicate (`gap_closing.py:80-180`). Instrument the same predicate path for status without changing its match decisions, including the mixed-category scalar fallback. Both bridges take one first-claim flat context (`:505-534`); call them on claim slices. Unavailable clinical/cross-claim fields remain missing, not inferred.
- **Payment traceability:** Its 42 rules are a secondary information scan and never change the primary payment-method decision (`payment_method.py:426-449,529-559`). Existing tests deliberately show an info row whose legacy `material_outcome` is `no_pay` (`tests/unit/domain/prose_rules/test_payment_method_traceability_for_context.py:204-235`); the new type must remain `traceability_info` and cannot enter either compliance or financial totals.
- **Treatment pricing:** The bridge is first-claim scoped and documents approximations; IVF cycles, BMI, session windows, scores, and other clinical facts are absent (`treatment_pricing.py:176-202,385-401,655-671`). Preserve current derivable predicate decisions; record unavailable keys for the rest. The comment in `billing/engine.py:223-225` cites an old rule count; use the active 202-row corpus, not that comment, as the inventory source.

## Public `validate_claim()` compatibility migration

`validate_claim()` currently delegates to `_validate_claim_via_context`, which flattens every `analyze_claim` row into `ClaimValidationResult.violations`, including `must_bill`, review, and payment info (`rule_engine.py:194-209,408-438,520-550`). `is_valid` then depends on error severity in that mixed list (`:566-567`). The public route copies that list (`api/routes/validation.py:39-64`), the chatbot independently mirrors it (`chatbot/tools.py:530-560`), and the frontend's validator labels `result.violations.length` as the number of violations (`frontend/src/lib/api/sut.ts:127-141`; `frontend/src/components/tabs/sut/sections/ClaimValidatorSection.tsx:310-333`). Existing catch-all/parity tests and an info-row smoke test assert the old mixed behavior (`tests/unit/domain/test_rule_engine_validate_claim.py:306-405`; `tests/unit/domain/test_validate_claim_adapter_parity.py:91-158`; `tests/smoke/test_sut.py:49-74`).

At the **single final activation**, retain the top-level `violations` field and every existing violation object's shape for actual adverse rows; add optional `advisories` (or equivalent typed positive/review/info array) to `ClaimValidationResult`, `ValidateClaimResponse`, route serialization, chatbot serialization, and the TypeScript client. Known frontend consumers must render advisories under their own label and calculate the violation KPI only from adverse `violations`. Derive both lists from the same typed batch/legacy financial rows without running detectors twice. Keep `n_bundling_violations`, `n_exclusion_violations`, material prices, summary shape, and existing monetary aggregation stable; compute `is_valid` from adverse error findings only. This is wire-format additive for legacy parsers because `violations` remains a list of the same row shape, but **its intentionally corrected contents are a semantic change** for clients that used positive/info rows there. Document that change and provide the new advisory field; do not preserve incorrect public violation counts as a compatibility alias. Update the existing catch-all and stent smoke expectations together, testing that no tagged motor row disappears and that permitted/info rows move to advisories.

## Staged checkpoints and release gates

1. **Inventory and outcome contract:** freeze the seven-file 496-ID/unique-ID matrix and source-family metadata; add corpus-driven classification tests for all authored rows, including payment's 9 false/33 null and drug combination's 12 null. Independently review classifications and unavailable-source policy. No runtime/UI activation.
2. **Predicate status and identity:** instrument the existing predicates, capture skip/missing reasons, slice per claim, and preserve dental priority and real material IDs. Per-family parity tests compare every currently firing legacy `(rule_id, claim_id, material/claim identity, message, outcome, money)` multiset against the **per-claim legacy call** baseline. The existing first-claim bridges already require claim slices; a whole-patient call is not an authoritative multi-claim oracle. Verify blocked rules cannot silently pass, plus mixed-category, branch, no-data, duplicate-name, and two-claim cases. No runtime/UI activation.
3. **One-pass canonical transport:** connect the broad batch to `billing/engine.py`, `billing/patient_report.py`, `billing/claim_compliance.py`, cache serialization, `billing/cohort_compliance.py`, patient API, and frontend Compliance view. Test stable finding/evaluation IDs across patient, cache, cohort, API, deep links, and old-cache fallback; monetary fields stay null and positive/review/info rows stay out of violation counts. Show actual findings and bounded status summaries, not 496 catalog rows. No runtime/UI activation.
4. **Public compatibility and full 25-group integration:** migrate `validate_claim`/route/chatbot/frontend validator with the other 18 focused groups; update intentional legacy tests, snapshot all existing financial totals, and run focused domain/API/cache/UI checks plus full backend, frontend, compiler/artifact, and hygiene gates. An unexplained emitted-ID change, status collision, source mismatch, or monetary drift blocks release.
5. **One activation:** build and inspect a staged patient/cohort cache, compare old/new financial values and identities, verify representative live triggers plus synthetic per-rule rare cases, then switch code/frontend/cache as one versioned tuple. Exercise rollback to the prior tuple before activation and verify production/cache build ID after. Partial checkpoint artifacts must never be visible in production (`tasks/todo.md:38-75`).
