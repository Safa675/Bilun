## Code Behavior (as implemented)

### Per-patient assembly
- Runs five blocks: lab, drug, copay, billing_strategy, materials (`compute_patient_billing_report` at ```122:198:src/bilun/domain/billing/orchestrator.py```).
- Routes to claim-line variants when `PatientClaimContext` is present (drug, copay, strategy, materials).

### Exact recoverable sum (gated)
- `_sum_exact_recoverable_try` includes savings only when block `exactness_status == "exact"` for: lab, drug, copay (visit + rx), billing_strategy (```49:61:src/bilun/domain/billing/orchestrator.py```).
- Materials are **excluded** from TRY totals (pre-check emits flags, not recoverable TRY) — consistent with `MaterialPreCheck` design.

### Report-level exactness propagation
- `_finalize_report_exactness` sets report to `exact` only if **all five** blocks are exact; otherwise `partial_exact` with `BILLING_REPORT_PARTIAL_REASON` (```73:97:src/bilun/domain/billing/orchestrator.py```).

### Cohort priority (percentile-based)
- After all reports built, patients with `total_recoverable_try > 0` are ranked; P75 → `high`, P50 → `medium`, else `low` (```321:338:src/bilun/domain/billing/orchestrator.py```).
- Priority uses **exactness-gated** `total_recoverable_try` — correct.

### Cohort aggregation (ungated totals)
- `summary.total_*_savings` and `grand_total_recoverable` sum each report's block savings **without** checking `exactness_status` (```345:367:src/bilun/domain/billing/orchestrator.py```).
- Cohort exactness: `_finalize_summary_exactness` marks summary `partial_exact` if any patient report is non-exact (```100:119:src/bilun/domain/billing/orchestrator.py```), but **does not zero or filter** category totals.

### Parallelism
- `ThreadPoolExecutor` when `max_workers > 1` (```312:316:src/bilun/domain/billing/orchestrator.py```).
