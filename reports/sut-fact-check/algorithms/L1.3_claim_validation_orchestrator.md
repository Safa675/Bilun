# L1.3: Claim Validation Orchestrator (`validate_claim`)

## Summary
- **Verdict:** PARTIAL
- **Severity:** medium

## Code Behavior (as implemented)

### Pipeline (5 steps)
1. Bundling: `check_bundling_violations(materials, procedure_code=procedure_code)` (```114:132:src/bilun/domain/rule_engine.py```)
2. Exclusion: `check_exclusion_violations(materials)` (```134:150:src/bilun/domain/rule_engine.py```)
3. Cost estimates: `estimate_material_costs(materials)` (```152:156:src/bilun/domain/rule_engine.py```)
4. Validity: `is_valid = not any(error severity)` (```158:160:src/bilun/domain/rule_engine.py```)
5. Summary string assembly (```162:191:src/bilun/domain/rule_engine.py```)

### Bundling child behavior
- `procedure_code` parameter accepted but **never used** in matching logic — only stored on violation dict (```29:55:src/bilun/domain/rules/bundling_rules.py```, ```102:128:src/bilun/domain/rules/bundling_rules.py```)
- `savings_try = billed_amount` (hospital line price, not gazette tariff)
- Severity: `error` if `billed > 50.0` else `warning` — **operational heuristic**, not SUT text

### Savings aggregation
- `total_savings_try` = sum of bundling violation savings only (exclusion uses `risk_amount`)
