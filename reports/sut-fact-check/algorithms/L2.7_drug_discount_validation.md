## Post-Fix Updates

**Status:** NEEDS_CLAIM_LINES is by design, not a bug. L2.7 was reviewed during Phase 3 post-fix sweep and confirmed to correctly gate on exact `DrugClaimLine` presence. The `unavailable_drug_discount_validation()` path returning `missing_exact_inputs` when no dispense lines are available is intentional exactness gating — the algorithm correctly refuses to infer discount tiers from catalog alone. No structural changes were needed.

Remaining PARTIAL verdicts (no runtime EK-4A catalog re-lookup, trusting preloaded `discount_tier_expected`) are acknowledged design decisions, not defects. A future EK-4A catalog join (P2) would add cross-validation but is not required for current compliance.
